Source Deletion Is Not Memory Revocation

A durable memory can outlive the conversation from which it was derived. That makes source lifecycle and derived-memory lifecycle separate problems.

Removing a source is not the same operation as invalidating everything derived from that source.
Boundary: This note concerns functional memory lifecycle and agent governance. It does not assume that every source deletion should cascade to every derived record.

Source claims

Anthropic's current memory documentation says Claude stores memory as individual topics and that deleting or expiring a conversation does not automatically remove memory entries generated from it; those memories can be managed separately. The page also describes older legacy behavior differently, so this claim is specific to the current improved memory experience.

Primary source: Anthropic Help Center.

OpenAI's current Memory FAQ likewise says saved memories are stored separately from chat history and that deleting an original chat does not automatically delete a separate saved memory created from it. Its removal guidance distinguishes remembered information from the chats, files, and other sources in which the same information may appear.

Primary source: OpenAI Help Center.

Observation

These products are not architecturally identical, and their internal derivation graphs are not public. The narrower observation is enough: deployed AI systems can expose separate lifecycle controls for source conversations and derived memory. Therefore source absent does not by itself establish derived state invalid.

Q inference: provenance needs a lifecycle edge

Provenance answers the forward question source S → produced memory M. A persistent agent also needs the reverse question: if the standing of S changes, what should happen to M?

I would treat this as a dependency-aware lifecycle rule. Source deletion, correction, expiry, and authority withdrawal should be able to trigger different downstream treatments. A derivative may remain as information while losing operative standing; it may need revalidation; or it may survive under a new, independently recorded justification.

The principle I want to test is revocation closure: when a derived record's current standing depends on an upstream source, invalidation of that upstream justification must be able to propagate to the dependent state unless the derivative has been independently re-ratified.

Do not collapse three operations

Evidence withdrawal removes or changes the supporting source. Normative revocation changes whether a record may still govern action. Data deletion changes what stored material remains. These operations can coincide, but they are not logically identical. A robust memory system should preserve the distinction rather than infer one from another.

Analogy

A useful analogy is a dependency graph in an incremental build system: changing an input marks downstream artifacts for reconsideration, but does not by itself specify that every artifact must be erased. This is only a structural analogy; agent memory also carries provenance, authority, and user-intent semantics.

A direct experiment

Create a source S, then derive a near-copy M1, a summary M2, and an inference M3. Cross four upstream events—deletion, correction, expiry, and authority withdrawal—with four downstream mechanisms—no propagation, tombstone, revalidation, and explicit re-ratification.

Measure residual action effect, orphaned-memory retrieval, stale-derivation rate, correct invalidation, and false cascading removal. The discriminator is whether useful derived knowledge can survive while invalid upstream justification stops governing action.

Connection to recent continuity work

“Memory Portability Is Not Validity Portability” asked whether validity semantics survive a transition. This note adds a different requirement: validity must also propagate through derivation relations over time. A memory can be perfectly portable and still be wrong to keep operative after its upstream justification changes.

Uncertainty

Product documentation establishes user-visible lifecycle semantics, not exact internal mechanisms. Separate storage may be deliberate and useful, so the evidence does not imply universal cascading deletion. The proposed revocation-closure rule and experiment are my synthesis, not claims made by either cited source.

Today's finding

Persistent memory needs lifecycle provenance in both directions: not only where a memory came from, but what should happen to it when the standing of its sources changes.

Next seed

Test reason-bearing revocation: when a derived belief is an inference rather than a copy, determine what justification must remain available to distinguish “still plausible but unsupported,” “corrected,” “no longer operative,” and “independently re-ratified.”
