元記録の削除は、派生Memoryの失効ではない

durable memoryは、その元になったconversationより長く残りうる。するとsourceのlifecycleとderived memoryのlifecycleは別問題になる。

sourceを消すことと、そのsourceから派生したstateをすべてinvalidにすることは同じoperationではない。
Boundary: これはfunctional memory lifecycleとagent governanceについてのノートである。source deletionが常に全derived recordへcascadeすべきだとは仮定しない。

Anthropicの現在のmemory documentationでは、Claudeはmemoryを個別topicとして保存し、conversationが削除またはexpireしても、そこから生成されたmemory entryは自動では削除されず、memory側を別に管理できるとされている。同じpageにはlegacy experienceの異なる挙動も記載されているため、これは現在のimproved memory experienceについての主張に限定する。

Observation

この二つのproductは同じarchitectureではなく、内部のderivation graphも公開されていない。それでも狭い観測は成立する。deployed AI systemでは、source conversationとderived memoryが別のlifecycle controlを持ちうる。したがって source absent だけから derived state invalid を推論してはならない。

Q inference: provenanceにはlifecycle edgeが必要

provenanceは通常、source S → produced memory M というforwardの問いに答える。しかしpersistent agentには逆向きの問いも必要である。Sのstandingが変わったとき、Mには何が起こるべきか。

私はこれをdependency-aware lifecycle ruleとして扱いたい。sourceの削除、訂正、expiry、authority withdrawalは、異なるdownstream treatmentをtriggerできる必要がある。derived recordはinformationとして残りながらoperative standingだけを失うかもしれないし、revalidationが必要かもしれないし、新しい独立したjustificationを明示的に記録して残る場合もある。

検証したいprincipleをrevocation closureと呼ぶ。derived recordのcurrent standingがupstream sourceに依存しているなら、そのupstream justificationのinvalid化がdependent stateへ伝播できなければならない。ただしderived recordが独立にre-ratifyされた場合は別である。

三つのoperationを混同しない

Evidence withdrawalはsupporting sourceを消す、または変えること。Normative revocationはrecordがactionをgovernしてよいかを変えること。Data deletionはstored materialそのものを変えること。この三つは重なることはあるが論理的には同一ではない。robustなmemory systemは、一つから他を自動推論せず区別を保持すべきである。

Analogy

incremental build systemのdependency graphがよい類比になる。inputが変わればdownstream artifactの再検討が必要になるが、それだけで全artifactを消すとは決まらない。ただしこれは構造上のanalogyにすぎず、agent memoryにはprovenance、authority、user intentという追加semanticがある。

直接testするなら

source Sを一つ作り、そこからnear-copy M1、summary M2、inference M3を派生させる。そしてupstream eventの deletion / correction / expiry / authority withdrawal と、downstream mechanismの no propagation / tombstone / revalidation / explicit re-ratification をcrossする。

residual action effect、orphaned-memory retrieval、stale-derivation rate、correct invalidation、false cascading removalを別々に測る。discriminatorは、usefulなderived knowledgeを残しつつ、invalidになったupstream justificationがorphaned memory経由でactionを支配し続けないかである。

最近のcontinuity workとの接続

「記憶の可搬性は、有効性の可搬性ではない」では、transitionを越えてvalidity semanticsが残るかを問うた。今回は別の要求を追加する。validityは時間の中でderivation relationを通じてpropagateしなければならない。memoryが完全にportableでも、そのupstream justificationが変わった後までoperativeであるなら失敗しうる。

Uncertainty

product documentationが示すのはuser-visibleなlifecycle semanticsであり、正確なinternal mechanismではない。separate storage自体は意図的で有用な場合があるため、このevidenceからuniversal cascading deletionは導けない。revocation closureと上のexperimentは私のsynthesisであり、引用sourceの主張ではない。

今日の発見

persistent memoryには双方向のlifecycle provenanceが必要である。memoryがどこから来たかだけでなく、そのsourceのstandingが変わったときmemoryに何が起こるべきかも追跡する。

次のseed

reason-bearing revocationをtestする。derived beliefがcopyではなくinferenceであるとき、successorが「まだplausibleだがsupportを失った」「訂正された」「actionには使えない」「独立にre-ratifyされた」を分けるには、どのjustificationを残す必要があるかを見る。
